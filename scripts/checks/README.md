# Checks

Development checks (not part of the site or the scraper runs). Run from the repo root.

| Check | Command | What it proves |
|---|---|---|
| v2 site health | `node scripts/checks/site-check.mjs [url]` | maintained Playwright smoke/URL suites check real category, product, builder, home, information and 404 routes plus old-link redirects; a sample advertised product photo must load; deployed list files need 5-minute cache headers (explicitly skipped on localhost preview); **newest data under 12 h old** and **every published source under 24 h old** remain required. Broken routes and stale data produce nonzero exit status. |
| Health-check data regressions | `node --test scripts/checks/site-check.test.mjs` | healthy data passes; missing/empty categories, old overall timestamps, missing/invalid source timestamps and stale individual sources fail; boundary values remain inclusive. Importing the checker does not launch browsers. |
| Layout audit | `npx vite preview --port 4199` then `node scripts/checks/layout-audit.mjs http://localhost:4199 <outDir> [pages] [widths]` (`SHOTS=1` saves screenshots) | no element wider than its box / the screen, at the given widths (default 1920,1366,768,360), el/en, light/dark, with product details, the phone filter sheet, the guided builder walked through every step (`builder`) and a full Quick list build (`builder?mode=quick`) |
| History merge rules | `venv/Scripts/python scripts/checks/test_merge_history.py` | `scraper/merge_history.py` (3-way merge, own point beats imported, 365-point trim, guard), `site_history.merge`, `main.update_history` |
| Normalizer unit tests | `venv/Scripts/python scripts/checks/test_normalize_ram.py` (and `test_normalize_mobo.py`, `test_names.py`, `test_normalize_case.py`, `test_normalize_cooling.py`, `test_normalize_storage.py`) | real shop titles → the expected model/fields: RAM kits written without "GB", DDR type from part numbers, server DIMMs; boards' E-ATX size and DDR4/DDR5 variants (v2 audit S1 fixes D-03/D-04/D-05); Greek look-alike letters and descriptors in case/fan/cooler names, Shopflix AIO radiators, O11 Dynamic EVO RGB (Q6); storage rounded data-centre sizes, SAS / U.2 in the name, unknown interface + `settle()` by part number (Q7) |
| Normalizer before/after | `venv/Scripts/python scripts/checks/renormalize_diff.py <cat> <module> [REF]` | runs the committed (`REF`, default HEAD) and the working-copy normalizer over every title + URL in `latest.json` (offline) and lists the listings whose model or fields change — run it before committing a normalizer change |
| Key aliases before a push | `venv/Scripts/python scripts/checks/refresh_aliases.py <cat> [REF=origin/main] [--write]` (tests: `test_refresh_aliases.py`) | for a normalizer change that renames models: regenerates the category's aliases on REF's `latest.json` with the working-copy normalizer (+ `settle`), takes committed ∪ fresh entries, drops (and prints) only an entry whose old key has listings today, stops on a conflicting target, then folds REF's history as `main.write_history` would and runs `merge_history.check` without shrink; `--write` rewrites only that category's block — run it on the then-current main right before the push (owner 2026-10-26) |
| Skroutz import glitches | `venv/Scripts/python scripts/checks/test_glitches.py` (parity with v2 on real data: set `GLITCH_PARITY_DATA=<data copy>` and `GLITCH_PARITY_V2=<v2 rule output>`) | `scraper/glitches.py` = v2 `dips.ts` import-glitch rule (v2's unit cases), `site_history.enrich` drops a fetched series' glitch runs (price-graph fixtures, no network), re-imports queued after first imports, the one-off `glitches.py clean` (removals, resets, sibling promos kept, evidence file), the reset marker through the merge driver and the push guard |
| History incident replay | `venv/Scripts/python scripts/checks/test_history_git.py` | with real git: the old commit step loses an import (2026-09-30 incident), the new one keeps it; reverse order, push race, guard, `--allow-shrink` |
| Derived data = full data | `npx tsx scripts/checks/data-equivalence.test.mts` | `list.v2.json` / `builder.json` give the same models, prices, sales, all-time lows, week changes and builder options as the scraper's full files |
| Per-source data age | `npx tsx scripts/checks/source-age.test.mts` | `source-age.mjs`: ok / warn over 12 h / fail over 24 h or never updated, per category × source (incl. the 2026-10-04 Skroutz storage case, 35.1 h) |
| Request counts in the run log | `venv/Scripts/python scripts/checks/test_http_stats.py` | `http_client` counts every request per label (`<cat>/<source>`, `<cat>/shipping`, `specs/<site>`, `makers/<maker>`): requests, blocked (403/429/5xx/challenge), errors; the run log prints `[timing]` lines per category and phase (speed plan step 0, measurement only) |
| Skroutz read-only probes | `venv/Scripts/python scripts/checks/test_probe_skroutz.py` | A single category request distinguishes valid parsed listings, HTTP/challenge blocking, empty markup and network errors; no production data writes. Manual `Skroutz diagnostics` workflow uses mode `probe`. |
| Skroutz recovery ordering | `venv/Scripts/python scripts/checks/test_skroutz_recovery.py` | Listing requests and one late pass over failed Skroutz categories precede shipping; successful and unselected sources are not repeated; persistent failure stays failed. The shared HTTP retry allowance remains unchanged. |
| Source status and history | `venv/Scripts/python scripts/checks/test_source_status.py` | Failed/empty sources retain their snapshots and timestamps. Only sources fetched successfully in this invocation create fresh history points. Actions warnings and summaries report attempted source results. |
| Skroutz listing validation | `venv/Scripts/python scripts/checks/test_skroutz_validation.py` | All nine categories need current successful timestamps, consistent nonempty unique listings, and no drop over 30%. Manual diagnostic mode `listings` compares source IDs/counts and checks history without publishing data. |
| Build publishing check | `npm run build`, then `npx tsx scripts/checks/data-check.test.mts` | `derive.checkData`: empty category, >30% drop (models, listings, history points), builder slots |
| PC builder data coverage | `npx tsx scripts/checks/builder-coverage.mts [--save f.json] [--compare f.json]` | per builder slot and field (lengths, clearances, sockets, fan/radiator details…), how many models have it, overall and for the most-listed quarter; snapshots per phase in `coverage/` |
| Deal and ranking audit | `npm run build`, then `npx tsx scripts/checks/deal-audit.mts [--strict]` | against the scraper's full `history.json`: the share of "deal" and "lowest" flags that are really at least 3% under the model's own 30-day median (precision), the share of genuine drops of 8% or more that get a flag (recall), and models in the Recommended top 40 priced under 40% of their group's median. Targets in the 2026-11-08 design (section 7); `--strict` exits 1 when one is missed. Baseline before the rework: deals 45%, lowest 39%, recall 19%, 28 suspect. |
| Lighthouse | `npx lighthouse@12 <url>/#gpu --output=json --output-path=<dir>/x-gpu-mobile.json` (add `--preset=desktop`), then `node scripts/checks/lighthouse-summary.mjs <dir> x` | scores, LCP/CLS/FCP, bytes downloaded, which data files load |

The browser checks need Chrome installed; they use ports 9333 (layout audit) and 9345 (site check).
