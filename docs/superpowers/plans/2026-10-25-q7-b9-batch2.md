## Change (rules, files)

1. `scraper/normalize_storage.py` `_snap`: a capacity within 1.5 % of a data-centre size (1.92, 3.84, 7.68, 15.36,
   30.72, 61.44, 122.88 TB = 960GB multiples) is that size. **Rule: capacities are written in TB with the maker's
   decimals ("1.92TB"), as makers and most titles write them; "1920GB" was already 1.92TB.** Untouched: 960GB, the
   mixed-use 1.6 / 3.2 / 6.4 / 12.8TB sizes, 1.8 / 2.4TB HDDs, 30TB HDDs (Exos M 30TB is 2.3 % from 30.72).
2. `normalize_storage.py` key suffixes (the "default adds nothing" rule, extended): **" SAS"** when the interface is
   SAS (SATA is the default; HDDs and SSDs); **" U.2"** for an NVMe drive whose form is U.2 / U.3 / 2.5" (M.2 2280 is
   the NVMe default). A series that already has the word SAS doesn't get it twice. An HDD that states no interface
   stays SATA (as today).
3. `normalize_storage._form_factor`: a 2.5" NVMe drive is `formFactor` "U.2" (118 listings change from '2.5"'; the tier
   rule already treated both as Server). HDDs: "1.8TB" / "2.5TB" is never the size (24 listings: 19 -> 2.5", 5 -> the
   3.5" default); a 10,000 / 15,000 rpm HDD with no stated size is 2.5" (1 listing today: Dell 400-BEGI).
4. `normalize_storage.SERVER_NAMES` (forced by the U.2 split, see "Tier"): Micron `[5-9]\d\d0` (was `[57]\d00`, which
   missed 7450 / 9550 / 7600) and Samsung `PM9D3a` (the `\b` after `9D3` missed the "a").
5. `scraper/model_aliases.json`: **464 new `storage` entries** (23 merge into an existing key, 441 renames), by Q3's
   rule (every listing of the old key moves to one new key, the old key has no listings left). Causes: SAS 261, U.2
   73, rounded capacity 47, U.2 + capacity 46, SAS + capacity 21, SAS + HDD 2.5" 13, HDD 2.5" 3. No hand-picked entry
   (see Splits). File ready at `work/model_aliases_q7.json` (the worktree's file = main's RAM + Q6's case/fan/cooler,
   plus storage); it resolves with no self-alias or cycle.
6. `scripts/checks/renormalize_diff.py`: compares `media`, `iface`, `tier` too (`renormalize_diff.py storage storage`).
   It reads the worktree's `public/data`, so for numbers use `work/numbers.py` (main's data copy).

### Judgment calls (shown, not just applied)

- **Split only interface and NVMe shape.** SATA vs SAS and M.2 vs U.2 are different products (different part
  numbers, different slots). Not split: SSD 2.5" vs 3.5" (Dell sells the same 345-xxxx part "with 3.5" hybrid
  carrier", and both shapes show the same part number), "PCIe card" (Skroutz writes it on the M.2 Kioxia Exceria G3
  and on the U.2 PM9D3a), M.2 2242 vs 2280 on SATA drives (one Transcend 420S listing).
- **The cheap side keeps the key.** The default shape (SATA, M.2 NVMe) adds nothing, so its models keep their key and
  their history; SAS / U.2 models are renamed (clean aliases) or new.
- **Shop errors follow the shop's words**: a Skroutz "SATA III" slug on a SAS part (Dell 400-ASGS, 161-BCHF) stays in
  the SATA model; the Shopflix "Adata Legend 860 500GB 2.5'' PCI Express 4.0" listing becomes its own U.2 model (it
  is an M.2 drive) - which also stops it making the whole Legend 860 500GB model "Server" today.
